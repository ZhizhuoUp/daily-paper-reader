## 摘要
模型预测控制 (MPC) 能够实现约束感知控制，但其对在线优化的依赖限制了其在具有快速动力学、高维模型或长时域系统中的应用。现有的 GPU 实现通常将设备视为线性代数加速器，导致优化循环依赖于重复的内核启动和高延迟的内存传输。本文介绍了 CUDA MPC，这是一个 GPU 原生的 MPC 框架，它针对 CUDA 硬件协同设计了优化算法、执行模型和内存架构。CUDA MPC 将时域并行交替方向乘子法 (ADMM) 分解与融合 CUDA 内核相结合，在设备上运行整个迭代求解过程。中间优化变量保留在低延迟的片上共享内存中，局部原子标志协议仅同步相邻的时域块，从而最大限度地减少了主机干预、内核调度开销和全局内存流量。在涵盖不断增加的状态维度和约束密度的六个非线性机器人基准测试中，CUDA MPC 在比 CPU 求解器长一到两个数量级的时域下保持了实时速率：它在 0.1 秒的采样间隔内解决了具有 100 秒前瞻量的基于优化的避障停车问题，并且是唯一一个在中心化 10 智能体集群中同时实现实时执行和无碰撞协调的评估求解器，而 acados 和 CasADi 则无法返回可行解，且每次求解分别需要 3.5 秒和 4.5 秒。与相同 ADMM 分解的张量框架实现相比，融合内核的速度提升了高达 965 倍。

## Abstract
Model Predictive Control (MPC) delivers constraint-aware control, but its reliance on online optimization limits its use on systems with fast dynamics, high-dimensional models, or long horizons. Existing GPU implementations typically treat the device as a linear-algebra accelerator, leaving the optimization loop dependent on repeated kernel launches and high-latency memory transfers. This paper introduces CUDA MPC, a GPU-native MPC framework that co-designs the optimization algorithm, execution model, and memory architecture for CUDA hardware. CUDA MPC pairs a parallel-in-horizon alternating direction method of multipliers (ADMM) splitting with a fused CUDA kernel that runs the entire iterative solve on the device. Intermediate optimization variables stay in low-latency, on-chip shared memory, and a localized atomic-flag protocol synchronizes only adjacent horizon blocks, minimizing host intervention, kernel-dispatch overhead, and global-memory traffic. Across six nonlinear robotics benchmarks spanning increasing state dimension and constraint density, CUDA MPC sustains real-time rates at horizons one to two orders of magnitude longer than CPU solvers: it solves an optimization-based collision-avoidance parking problem with 100 s of lookahead within a 0.1 s sampling interval, and is the only solver evaluated that achieves both real-time execution and collision-free coordination for a centralized 10-agent swarm, where acados and CasADi return no feasible solution and require 3.5 s and 4.5 s per solve. Against tensor-framework implementations of the same ADMM splitting, the fused kernel is up to $965\times$ faster.

### 1. 核心问题与整体含义（研究动机和背景）
模型预测控制（MPC）在处理具有复杂约束的机器人系统时表现优异，但其在线优化的计算负担极大，尤其是在面对**高维模型、长预测时域或快速动力学系统**时。
*   **现有痛点**：传统的 CPU 求解器（如 acados, CasADi）受限于串行计算；而现有的 GPU 加速方案通常仅将 GPU 作为线性代数加速器（如使用 PyTorch/JAX 框架），这会导致频繁的内核启动（Kernel Launch）开销和高延迟的全局内存（VRAM）数据交换，抵消了 GPU 的并行优势。
*   **核心目标**：开发一种“GPU 原生”的 MPC 求解器，通过算法与硬件架构的协同设计，消除通信瓶颈，实现超长时域的实时优化。

### 2. 方法论：核心思想与关键技术
CUDA MPC 在算法、执行和内存三个层面进行了协同设计：
*   **算法层（时域并行 ADMM）**：采用交替方向乘子法（ADMM）将优化问题分解为在预测时域上并行的子问题。通过引入局部副本和共识变量，使每个时间步的更新变得独立。对于非线性问题，外层使用序列凸规划（SCP）进行线性化。
*   **执行层（融合内核与局部同步）**：
    *   **内核融合（Kernel Fusion）**：将整个 ADMM 迭代循环封装在单个 CUDA 内核中，避免了迭代过程中 CPU 与 GPU 的反复通信。
    *   **邻域局部同步协议**：放弃了昂贵的全局网格同步（Grid-wide barrier），改用基于原子标志（Atomic-flag）的邻域同步，仅在相邻的时域块之间交换边界变量，使协调开销与时域长度解耦。
*   **内存层（I/O 感知架构）**：借鉴 FlashAttention 的思想，将所有中间优化变量（原变量、对偶变量、共识变量）保留在低延迟的**片上共享内存（Shared Memory）**中，最大限度减少对高延迟全局内存的访问。

### 3. 实验设计
论文通过两个主要研究验证了 CUDA MPC 的性能：
*   **研究一：与张量框架对比**。在 AFTI-16 飞机模型上，对比了基于 PyTorch 和 Julia 实现的相同 ADMM 算法（$\pi$MPC）。
*   **研究二：非线性机器人基准测试**。涵盖 6 个场景：单摆（Pendulum）、小车倒立摆（Cart-Pole）、基于优化避障的停车（Car Parking）、卡车拖车倒车（Truck-Trailer）、无人机携带摆杆（Quadcopter-Pole）以及 10 智能体集群控制（Centralized Swarm）。

### 5. 实验数量与充分性
*   **实验规模**：涵盖了从 2 维到 40 维状态空间的 6 种不同复杂度的机器人任务，预测时域 $N$ 从 5 跨越到 1000。
*   **充分性评价**：实验设计非常充分且具有说服力。不仅对比了计算速度（Solve Time），还评估了闭环控制性能（RMSE）和可行性。特别是针对长时域任务（如 100 秒前瞻的停车问题）和高维多智能体任务，展示了 CUDA MPC 在其他求解器失效时的独特优势。

### 6. 主要结论与发现
*   **极致加速**：在相同算法下，CUDA MPC 比 PyTorch 实现快达 **965 倍**。在 $N=1000$ 时，内核启动次数从 17 万次减少到 1 次，内存流量从 17.4 GB 降至 31.2 MB。
*   **长时域实时性**：CUDA MPC 能够在 0.1 秒内处理长达 1000 步的预测时域，而 CPU 求解器在时域超过 100 步后通常无法满足实时性要求。
*   **复杂任务突破**：在 10 智能体集群控制中，CUDA MPC 是唯一能同时实现实时执行（~28ms）和无碰撞协调的求解器，而 acados 和 CasADi 均无法在实时范围内给出可行解。

### 7. 优点
*   **硬件深度优化**：通过内核融合和共享内存利用，彻底解决了 GPU 在小规模迭代计算中的延迟问题。
*   **可扩展性**：邻域同步协议使得计算时间随预测时域的增长非常缓慢，适合超长时域规划。
*   **通用性**：通过 SCP 框架，能够处理非线性动力学和非凸约束（如 OBCA 避障约束）。

### 8. 不足与局限
*   **状态维度限制**：由于依赖片上共享内存，而共享内存容量有限（如每块 48-96KB），当系统状态维度极高时，可能无法将整个工作集放入共享内存，导致性能下降。
*   **一阶方法收敛性**：作为基于 ADMM 的一阶求解器，在某些对精度要求极高的任务中，其收敛速度和局部精度可能不如基于二阶信息的 CPU 求解器（如 HPIPM）。
*   **硬件依赖**：该框架高度依赖 NVIDIA CUDA 架构，移植到其他硬件平台（如 AMD GPU 或 TPU）需要重新设计底层逻辑。
