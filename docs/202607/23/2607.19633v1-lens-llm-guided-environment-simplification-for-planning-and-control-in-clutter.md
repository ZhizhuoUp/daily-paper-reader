## 摘要
尽管通用机器人操作最近取得了进展，但现实世界中的多物体杂乱环境对于当今的主流方法来说仍然具有挑战性。由于物体和碰撞增多、接触物理更加不可预测、干扰物以及任务歧义，问题的复杂性随之增加。弥合这一差距以实现现实部署需要有效的场景抽象；然而，目前生成此类抽象需要大量的特定任务手动工程，这不具备可扩展性。这些抽象的生成成本高昂，且难以调整或微调。与此相对，我们提出了一种即插即用的修复方案，在现有的规划和控制栈之上自动生成特定于场景、特定于任务且自适应更新的抽象。大语言模型引导的环境简化（LENS）通过根据任务进度在闭环中合并（例如堆叠物体）或剪枝（例如远处物体）场景实体，生成去杂乱的抽象场景表示。这些动态的、与任务相关的抽象具有通用性且易于使用。在我们的实验中，我们展示了 LENS 在各种高度杂乱的操作场景中改进了经典规划、基于模型的控制以及视觉-语言-动作模型。项目网站：https://lens-2026.github.io/。

## Abstract
Despite recent advances in general-purpose robotic manipulation, real-world multi-object clutter remains challenging to handle for today's prevalent approaches. The problem scales in complexity due to more objects and collisions, more unpredictable contact physics, distractors, and task ambiguity. Bridging this gap to real-world deployment requires effective scene abstractions; yet today, producing such abstractions requires extensive task-specific manual engineering, which does not scale. These abstractions are costly to generate and difficult to adjust or fine-tune. We instead propose a plug-and-play fix to automatically generate scene-specific, task-specific, adaptively updating abstractions on top of existing planning and control stacks. LLM-guided Environment Simplification (LENS) produces a de-cluttered abstracted scene representation by merging (e.g., stacked objects) or pruning (e.g., distant objects) scene entities in a closed loop in response to task progress. These dynamic, task-relevant abstractions are versatile and easy to use. In our experiments, we show that LENS improves classical planning, model-based control, and a vision-language-action model, across a diverse set of highly cluttered manipulation scenes. ### 2. 方法论：核心思想与技术细节
LENS 的核心思想是**“在闭环中通过 LLM 引导环境简化”**。它作为一个即插即用的模块，位于感知层和控制层之间。

*   **核心流程**：
    1.  **感知与描述**：获取场景中所有物体的列表及其空间关系（如“物体A在物体B上面”）。
    2.  **LLM 推理**：将任务目标（如“拿起最底层的盘子”）和物体列表输入 LLM。LLM 根据常识判断哪些物体可以被简化。
    3.  **简化操作**：
        *   **合并 (Merging)**：将物理上连接或共同移动的物体（如一叠盘子）视为一个单一的复合实体，减少需要处理的实体数量。
        *   **剪枝 (Pruning)**：移除与当前任务无关的干扰物体（如远处的杯子），减少碰撞检测的负担。
    4.  **下游执行**：将简化后的场景输入给现有的控制器（如路径规划器、MPC 或 VLA 模型）。
    5.  **闭环更新**：随着任务进展（如移走了一个物体），LENS 会重新评估并更新简化策略。

*   **性能提升**：在所有测试的控制器中，LENS 均显著提高了任务成功率。例如，在经典规划任务中，简化场景使规划速度提升了数倍，并解决了原始场景下因碰撞检测过载导致的失败。
*   **VLA 的增强**：对于 OpenVLA 等模型，LENS 通过移除视觉干扰项，显著缓解了模型在复杂背景下的“注意力分散”问题。
*   **自适应性**：LLM 能够根据任务描述准确识别哪些物体是“障碍”而哪些是“背景”，这种语义理解是传统几何方法缺失的。

### 7. 优点
*   **即插即用**：不需要修改现有的底层控制算法，具有极强的兼容性。
*   **自动化抽象**：解决了机器人领域长期存在的“手动设计场景抽象”的痛点。
*   **鲁棒性**：通过闭环机制，即使 LLM 在某一步做出了错误的简化，也可以在下一步纠正。

### 8. 不足与局限
*   **LLM 延迟与成本**：依赖云端 LLM API 会带来推理延迟，不适合极高频的动态避障任务。
*   **过度简化的风险**：如果 LLM 错误地剪枝掉了一个关键的潜在碰撞体，可能会导致机器人发生物理碰撞。
*   **感知依赖**：LENS 假设已经存在一个可靠的物体检测和位姿估计系统，如果感知层失效，LENS 的推理基础将不复存在。
*   **实验环境**：主要集中在仿真环境，现实世界中的传感器噪声和不确定性可能对 LLM 的描述输入产生影响。
